# Единая модель показателей натальной карты

**Этап:** 19 — единая модель показателей натальной карты  
**Статус реализации:** реализовано и проверено полным `npm run verify` — [GitHub Actions run 42837608885](https://github.com/TamiArt/AstroDay/actions/runs/42837608885), commit `a7a4f208f3d2fbb6e0f35c435eadd846dd0f81ff`  
**Источник:** `src/app/utils/natalChartFacts.ts`

## Назначение

`buildNatalChartFacts(chart)` формирует единый нормализованный снимок астрологических фактов и связей конкретной натальной карты. Модель отделяет вычисленные показатели от интерпретационных формулировок. Интерпретационные модули должны читать факты из этого слоя, а не независимо пересчитывать знак, дом, управителя или аспект.

Модель не заменяет эфемеридный расчёт в `astrology.ts`: она собирает и согласует уже рассчитанные положения и методы анализа, фиксирует происхождение связей и явно показывает пробелы данных.

## Структура

### 1. Метаданные карты

- дата рождения в ISO 8601;
- координаты места рождения;
- знак, градус, накшатра и пада Асцендента, если значения доступны;
- версия схемы данных.

### 2. Девять грах

Для каждой из девяти поддерживаемых грах модель хранит:

- ключ и отображаемое имя;
- сидерический знак и индекс знака;
- абсолютную сидерическую долготу и градус в знаке;
- накшатру, индекс накшатры и паду;
- дом по Whole Sign либо `null`, если его нельзя определить;
- список управляемых домов;
- диспозитора знака и дом диспозитора;
- достоинство из существующего валидированного оценщика;
- соединения по знаку;
- исходящие аспекты на дома и планеты;
- входящие межпланетные аспекты;
- статусы доступности ключевых показателей.

### 3. Двенадцать домов

Для каждого присутствующего дома доступны:

- номер, знак и управитель;
- дом положения управителя;
- планеты-обитатели;
- планеты, аспектирующие дом;
- остальные дома под управлением того же управителя;
- флаги доступности управителя и его положения.

Отсутствующий дом не создаётся искусственно. Если дом управителя не вычисляется, сохраняется `null`, а не фиктивный 1-й дом.

### 4. Граф связей

Каждая связь имеет стабильный ID, тип, исходный и целевой узел, подписи, метод и текстовое evidence.

Поддерживаются отношения:

| Тип | Значение |
|---|---|
| `occupies-house` | Планета расположена в доме |
| `rules-house` | Планета управляет домом |
| `dispositor-of` | Планета является диспозитором другой планеты |
| `aspects-house` | Планета аспектирует дом |
| `aspects-planet` | Межпланетный аспект по используемой схеме |
| `conjuncts` | Планеты находятся в одном сидерическом знаке |
| `house-lord-placed-in` | Управитель дома расположен в другом доме |
| `shares-ruler-with` | Два дома имеют общего управителя |

Повторяющиеся связи с одинаковым типом и парой узлов не дублируются.

## Методология и границы

Модель явно фиксирует текущие правила проекта:

- сидерический зодиак;
- аянамша Лахири;
- система домов Whole Sign;
- классическая схема Parashari graha drishti;
- соединение фиксируется по одному знаку, без заявления о точном орбисе;
- аспекты Раху/Кету не включаются, поскольку правила различаются между школами; соединения узлов по знаку сохраняются.

Ретроградность и сожжение не выводятся по косвенным признакам. Они перечислены в `unsupportedFactors`, поскольку текущий источник `PlanetPosition` не содержит необходимых валидированных показателей. Это предотвращает ложную точность.

## Качество и неполные данные

`dataQuality` содержит:

- количество доступных планет;
- список отсутствующих планет;
- список отсутствующих домов;
- предупреждения о неопределённых домах и диспозиторах;
- факторы, которые текущая модель не рассчитывает.

Неизвестное значение остаётся `null` или явно отсутствующей записью. Модель не подменяет его первым домом, не выводит ретроградность/сожжение из догадок и не трактует отсутствие аспекта как отсутствие любых жизненных влияний.

## Интеграция

- `NatalAnalysisTab` строит один снимок `NatalChartFacts` и повторно использует его для персональных блоков Асцендента, Солнца и Луны.
- `natalPersonalFocus.ts` формирует chart-aware тексты на основании канонических фактов.
- `personalizedHouseAnalysis.ts` использует общую модель для знаков домов, управителей, положения управителей, обитателей и аспектов.
- `natalHouseLordAnalysis.ts` использует те же данные для положения управителей, достоинства, управляемых домов и соединений.
- Публичные селекторы `getNatalPlanetFacts`, `getNatalHouseFacts`, `getNatalFactLinks` дают потребителям типизированный доступ к модели.

## Проверки

Регрессионные проверки подтверждают:

- все 9 грах и 12 домов в полной карте;
- корректность знака, дома, диспозитора, достоинства и управляемых домов для контрольной карты;
- наличие связей «управляет», «диспозитор», «общий управитель» и «аспектирует»;
- использование связей между Марсом и Юпитером по заявленной схеме;
- отсутствие выдуманного 1-го дома при удалённом доме;
- явную регистрацию отсутствующей планеты;
- наличие ограничений по ретроградности, сожжению и точным орбисам.

Модель является единым техническим источником данных, а не заявлением о научной валидности астрологических интерпретаций.
