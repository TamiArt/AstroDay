# Углублённая проверка йог и специальных комбинаций

## Назначение

Модуль `src/app/utils/natalYogaAnalysis.ts` выполняет детерминированную проверку ограниченного набора классических комбинаций Джйотиш на основе `NatalChartFacts`. Он не пересчитывает положения планет и аспекты, а использует канонические факты натальной карты.

## Проверяемые правила

| Комбинация | Формальное условие в реализации |
|---|---|
| Гаджа-Кесари | Юпитер находится в 1/4/7/10-м знаке от Луны |
| Буддха-Адитья | Солнце и Меркурий находятся в одном сидерическом знаке |
| Чандра-Мангала | Луна и Марс находятся в одном знаке или связаны рассчитанным Parashari graha drishti |
| Панча-Махапуруша | Ручака: Марс в собственном знаке/экзальтации в кендре от Лагны; Бхадра: аналогично для Меркурия; Хамса — для Юпитера; Малавья — для Венеры; Шаша — для Сатурна |
| Раджа-йога | Управитель 4/7/10-го дома связан соединением по знаку, аспектом Parashari или обменом знаками с управителем 1/5/9-го дома |
| Дхана-йога | Управитель 2/11-го дома связан теми же отношениями с управителем 1/5/9-го дома |
| Паривартана | Две классические планеты находятся в знаках друг друга |
| Випарита-раджа | Управитель 6/8/12-го дома расположен в одном из домов 6/8/12 |

Для Раджа-, Дхана-, Паривартана- и Випарита-правил возвращаются все обнаруженные сочетания, а не только первое совпадение. Каждая комбинация имеет стабильный ID, участников, связанные дома, формальное условие и отдельные доказательства.

## Статусы проверки

- `detected` — обнаружено хотя бы одно сочетание. `findingIds` содержит все найденные ID; при неполных дополнительных данных список `missingFacts` предупреждает, что поиск мог быть неполным.
- `not-detected` — правило проверено на необходимых данных, совпадений нет.
- `incomplete` — отсутствуют обязательные исходные данные, поэтому отрицательный вывод делать нельзя.

## Evidence и ограничения

- Evidence формируется из фактических знаков, домов, управителей и рассчитанных аспектов.
- Соединение фиксируется по общему сидерическому знаку. Точный орбис не заявляется.
- Для Панча-Махапуруша используются фиксированные знаки собственного достоинства и экзальтации в сочетании с кендрой 1/4/7/10 от Асцендента.
- Для обмена знаками используется традиционная семипланетная схема управителей. Раху/Кету не используются как управители или источники аспектов.
- Не рассчитываются Shadbala, авастхи, сожжение, ретроградность, точные орбисы, все исключения и все варианты классификации отдельных школ. В частности, обмен знаками не классифицируется автоматически как Maha/Kahala/Dhana Parivartana.
- Найденная йога — результат формальной символической модели, а не гарантия события, богатства, статуса, брака, здоровья или иных жизненных исходов.

## Интеграция

Раздел «Йоги и специальные комбинации» встроен в анализ натальной карты. Он показывает найденные комбинации с раскрываемыми формальными правилами и доказательствами, количество непроверенных/необнаруженных правил, полноту данных и методические ограничения.

## Проверки

`src/app/utils/natalYogaAnalysis.test.ts` проверяет обнаружение Раджа-, Дхана-, Паривартана-, Випарита-, Панча-Махапуруша-, Гаджа-Кесари-, Буддха-Адитья- и Чандра-Мангала-комбинаций, наличие evidence и formalRule, уникальность ID, различение неполных данных и отсутствие ложного отрицательного вывода. Тест включён в `npm run test:unit`.
