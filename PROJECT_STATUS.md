## Текущее состояние

AstroDay — клиентское приложение на React 18, TypeScript и Vite. Расчёты и хранение пользовательских данных выполняются преимущественно в браузере. OpenStreetMap Nominatim используется для геокодирования.

### Реализованные области

- Профиль рождения, геокодирование, координаты и IANA timezone.
- Натальная карта, Лагна, Whole Sign, планеты, накшатры/пады, средние лунные узлы, Вимшоттари-даша.
- Панчанг, планетарные часы, транзитные показатели, календарь прогнозов и персональные рекомендации.
- Восемь ежедневных сфер и восемь подробных натальных жизненных направлений.
- Анализ 12 домов, управителей, диспозиторов, соединений по знаку и классических граха-дришти.
- Дробные карты D1/D2/D3/D4/D7/D9/D10/D12/D16/D20/D24/D27: отдельные правила Парашари, тематические evidence, сравнение с D1 и чувствительность Лагны; D60 остаётся экспериментальной общей формулой.
- Вимшоттари-даша: Махадаша, Антардаша и Пратьянтардаша; начальные подпериоды рассчитываются от полной теоретической Махадаши и обрезаются по моменту рождения.
- Васту: девять секторов, ориентация входа/участка, назначение помещений, технический и юридический чек-лист, предварительная финансовая модель объекта.
- Отдельный профиль партнёра, межкартное сравнение и полный расчёт Ашта-Кута / Гуна-милан по восьми кутам (36 баллов) с объяснимыми промежуточными значениями.
- Локальное хранение профиля, партнёра и данных дома; IndexedDB используется для кэша прогнозов.
- Экспорт PDF и JSON-пакета локальных данных.

Из `package.json`:

- `npm run typecheck` — `tsc --noEmit`.
- `npm run test:unit` — полный перечисленный в package.json unit suite через `tsx`.
- `npm run build` — production build через Vite.
- `npm run verify` — строгий TypeScript check с `noUnusedLocals` и `noUnusedParameters`, затем unit suite, затем production build.
- `npm audit` — аудит всех зависимостей; `npm audit --omit=dev` — аудит production-графа. Для изменений manifest/lock эти проверки выполняет отдельный workflow.

## Ограничения и незавершённые задачи

1. Астрономические эталоны покрывают только описанные в [ASTROLOGY_ACCURACY.md](docs/ASTROLOGY_ACCURACY.md) даты, объекты и допуски; это не полная сертификация эфемерид.
2. Mean Lahiri не включает nutation; Раху — средний узел; истинный узел не поддерживается.
3. D60 generic; полярный fallback планетарных часов оценочный; важные даты панчанга определяются дневной выборкой, а не точным временем события.
4. Астрологические интерпретации символические и не являются научно подтверждёнными предсказаниями.
5. Полный JSON-архив версии 1 восстанавливает профиль, обратную связь, данные дома, план помещения, прогресс, чек-лист Васту, оценку недвижимости и профиль партнёра. Старый полный JSON-пакет без версии также восстанавливается; отдельный старый JSON профиля обновляет только профиль.
6. Ошибки записи localStorage теперь передаются вызывающему коду и показываются в основных формах. Полный `npm run verify` для реализации этапа 10 и этапов 20–24 ещё должен быть подтверждён. См. [CODE_AUDIT.md](CODE_AUDIT.md).
7. XOR + Base64 — обратимая обфускация, а не криптографическое шифрование.
8. PWA/offline service worker, голосовой интерфейс и push-уведомления не реализованы. Ашта-Кута / Гуна-милан реализован; региональные варианты правил и расширенная синастрия остаются отдельными направлениями.
9. npm audit на проверенном lock-файле не выявил известных advisory; повторять аудит при каждом изменении зависимостей. Полный browser E2E-набор ещё не завершён.
