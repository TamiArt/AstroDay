## Текущее состояние

AstroDay — клиентское приложение на React 18, TypeScript и Vite. Расчёты и хранение пользовательских данных выполняются преимущественно в браузере. OpenStreetMap Nominatim используется для геокодирования.

### Реализованные области

- Профиль рождения, геокодирование, координаты и IANA timezone.
- Натальная карта, Лагна, Whole Sign, планеты, накшатры/пады, средние лунные узлы, Вимшоттари-даша.
- Панчанг, планетарные часы, транзитные показатели, календарь прогнозов и персональные рекомендации.
- Восемь ежедневных сфер и восемь подробных натальных жизненных направлений.
- Анализ 12 домов, управителей, диспозиторов, соединений по знаку и классических граха-дришти.
- Дробные карты с отдельными правилами для поддерживаемых варг; D60 остаётся generic.
- Васту: направления, план помещения, разметка объектов, чек-листы и данные недвижимости.
- Отдельный профиль партнёра и сопоставление карт. Полный Ашта-Кута / Гуна-милан не реализован.
- Локальное хранение профиля, партнёра и данных дома; IndexedDB используется для кэша прогнозов.
- Экспорт PDF и JSON-пакета локальных данных.

## Команды проверки

Из `package.json`:

- `npm run typecheck` — `tsc --noEmit`.
- `npm run test:unit` — полный перечисленный в package.json unit suite через `tsx`.
- `npm run build` — production build через Vite.
- `npm run verify` — строгий TypeScript check с `noUnusedLocals` и `noUnusedParameters`, затем unit suite, затем production build.

## Ограничения и незавершённые задачи

1. Астрономические эталоны покрывают только описанные в [ASTROLOGY_ACCURACY.md](docs/ASTROLOGY_ACCURACY.md) даты, объекты и допуски; это не полная сертификация эфемерид.
2. Mean Lahiri не включает nutation; Раху — средний узел; истинный узел не поддерживается.
3. D60 generic; полярный fallback планетарных часов оценочный; важные даты панчанга определяются дневной выборкой, а не точным временем события.
4. Астрологические интерпретации символические и не являются научно подтверждёнными предсказаниями.
5. Экспорт JSON включает профиль, обратную связь, данные дома, план помещения, прогресс, чек-лист Васту и профиль партнёра. `importUserProfile()` пока восстанавливает только профиль, не весь архив.
6. Storage-функции перехватывают ошибки записи localStorage; вызывающий код не всегда узнаёт о неудаче. См. [CODE_AUDIT.md](CODE_AUDIT.md).
7. XOR + Base64 — обратимая обфускация, а не криптографическое шифрование.
8. Полный Ашта-Кута / Гуна-милан, PWA/offline service worker, голосовой интерфейс и push-уведомления не реализованы.
9. Свежий аудит npm advisory и полный E2E-набор ещё не завершены.
